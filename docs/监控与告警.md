# 监控与告警

svngod 暴露两组指标，配合 Prometheus + node_exporter 即可覆盖“提交路径、副本一致性、缓存效率”三条主线。

## 1. 采集

### 1.1 服务端 `/metrics`

```yaml
# prometheus.yml
scrape_configs:
  - job_name: svngod
    metrics_path: /_metrics
    static_configs:
      - targets: ["svngod-1:8080", "svngod-2:8080"]
```

`/_metrics` 与 SVN 服务同端口（默认 `/_metrics`，可用 `svngod -metrics=false` 关闭）。**不要**把它暴露到公网：标签里包含仓库名，且没有任何认证。

### 1.2 副本一致性（textfile）

`svnadmin replicas` 可以把“多副本是否一致”写成 Prometheus textfile，交给 node_exporter 的 textfile collector：

```cron
*/10 * * * * svnadmin replicas -verify -quiet -textfile /var/lib/node_exporter/textfile/svngod-replicas.prom --mirror-file /etc/svngod/mirror.json <repo> || true
```

`svnadmin verify` 在发现完整性问题时以退出码 1 结束，可直接在 cron/监控里用退出码驱动告警：

```cron
# 每天凌晨全量校验；失败时由脚本发告警或写自定义指标
0 3 * * * svnadmin verify --all-revs --workers 4 --mirror-file /etc/svngod/mirror.json <repo> >/var/log/svngod/verify.log 2>&1 || notify "svngod verify failed"
```

## 2. 指标参考

| 指标 | 类型 | 含义 |
|---|---|---|
| `svngod_http_requests_total{method,status}` | counter | HTTP 请求数（按方法/状态码） |
| `svngod_http_request_duration_seconds_{sum,count}` | counter | 所有请求的累计耗时与次数 |
| `svngod_http_request_bytes_total` / `_response_bytes_total` | counter | 请求/响应字节数 |
| `svngod_commits_total` | counter | 已提交修订数（DAV + bundle） |
| `svngod_commit_duration_seconds_bucket{le}` / `_sum` / `_count` | histogram | MERGE（提交）延迟，桶 50ms…30s，可算 p50/p95/p99 |
| `svngod_commit_errors_total{reason}` | counter | 提交失败原因：`out_of_date`、`lease_busy`、`quorum`、`replica_lagging`、`index_conflict`、`lease_lost`、`other` |
| `svngod_upload_inflight` / `svngod_upload_limit` | gauge | 在途上传数与上限 |
| `svngod_bundle_uploads_total` / `svngod_bundle_replays_total` | counter | bundle 上传次数 / 幂等重放次数 |
| `svngod_mirror_healthy{repo,replica}` | gauge | 副本当前是否可达 |
| `svngod_mirror_primary{repo,replica}` | gauge | 该副本是否本进程的主写副本 |
| `svngod_mirror_last_write_seconds{repo,replica}` | gauge | 距上次成功写入的秒数（-1 = 未知） |
| `svngod_block_cache_hits_total{repo}` / `_misses_total` | counter | 修订块缓存命中/未命中 |
| `svngod_segment_cache_hits_total{repo}` / `_misses_total` | counter | 已解码段缓存命中/未命中 |
| `svngod_replica_head{repo,member}` | gauge | 各成员报告 HEAD |
| `svngod_replica_verify_issues{repo,member}` | gauge | 各成员校验问题数（-1 = 校验执行失败） |
| `svngod_replica_consistent{repo}` | gauge | 1 = 各成员 head/uuid/索引摘要一致 |

## 3. 告警规则示例

```yaml
groups:
  - name: svngod
    rules:
      - alert: SvgodCommitSlow
        expr: |
          histogram_quantile(0.95,
            sum by (le) (rate(svngod_commit_duration_seconds_bucket[10m]))) > 2
        for: 15m
        labels: {severity: warning}
        annotations:
          summary: "提交 p95 > 2s"
          description: "持续 15 分钟；检查后端延迟、租约争用与组提交配置。"

      - alert: SvgodCommitBackendErrors
        expr: |
          sum by (reason) (rate(svngod_commit_errors_total{reason=~"quorum|replica_lagging|lease_busy|index_conflict|lease_lost"}[5m])) > 0
        for: 5m
        labels: {severity: critical}
        annotations:
          summary: "提交因后端问题失败 ({{ $labels.reason }})"
          description: "out_of_date 是客户端冲突，可忽略；这几类说明存储/副本出了问题。"

      - alert: SvgodMirrorUnhealthy
        expr: svngod_mirror_healthy == 0
        for: 5m
        labels: {severity: warning}
        annotations:
          summary: "副本 {{ $labels.replica }} 不可达（仓库 {{ $labels.repo }}）"

      - alert: SvgodMirrorLagging
        expr: svngod_mirror_last_write_seconds > 120
        for: 10m
        labels: {severity: warning}
        annotations:
          summary: "副本 {{ $labels.replica }} 超过 2 分钟没有成功写入"

      - alert: SvgodReplicaDrift
        expr: svngod_replica_consistent == 0
        for: 20m
        labels: {severity: critical}
        annotations:
          summary: "仓库 {{ $labels.repo }} 的副本不一致"
          description: "运行 `svnadmin replicas -repair`，随后 `verify --all-revs`。"

      - alert: SvgodCacheMissStorm
        expr: |
          sum by (repo) (rate(svngod_block_cache_misses_total[5m]))
            / clamp_min(sum by (repo) (rate(svngod_block_cache_hits_total[5m]) + rate(svngod_block_cache_misses_total[5m])), 0.001) > 0.9
        for: 30m
        labels: {severity: info}
        annotations:
          summary: "仓库 {{ $labels.repo }} 块缓存命中率 < 10%"
```

## 4. 值班处置顺序

1. **`SvgodCommitBackendErrors`（critical）**：先看 `svngod_mirror_*`，确认是副本掉线还是法定人数不足；`svnadmin replicas -quiet -verify --mirror-file ...` 看是否漂移；必要时 `-repair-mirror` 补齐，再 `-repair-index`。
2. **`SvgodReplicaDrift`**：`replicas -repair`（先镜像补齐，再逐成员重建索引、清理死覆盖），随后 `replicas -verify` 与 `svnadmin verify --all-revs`。
3. **`SvgodCommitSlow`**：查 `svngod_commit_errors_total{reason="lease_busy"}` 是否升高（多进程争用）；查后端延迟与 `svngod_mirror_last_write_seconds`。
4. **磁盘回收**：`svnadmin gc -dry-run` 先看可回收量，再执行 `svnadmin gc`；大仓库用 `--progress` 观察阶段进度。

## 5. 容量与巡检建议

- 每 6 小时：`svnadmin replicas -verify -quiet -textfile ...`；
- 每天：`svnadmin verify --all-revs --workers 4`（20 万修订约 4 秒；千万级按分片并行）；
- 每周：`svnadmin gc -dry-run` 观察增长，再执行 `svnadmin gc`；
- 变更窗口：`svnadmin gc --compact=false` 可只做回收不做合并。
