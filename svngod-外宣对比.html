svngod 与原生 SVN 的差异

架构 / 存储 / 并发
维度svngod原生 SVN（FSFS / mod_dav_svn）
进程模型 单进程、单二进制；一个 svngod 进程可托管多个独立仓库（--config），部署与扩容简单 多进程 / 多组件：Apache httpd + mod_dav_svn 或 svnserve，需搭配进程管理与配置
存储后端 本地盘 / S3 对象存储（RustFS）/ 混合主备镜像 三者任意组合，可直接落到对象存储 仅本地文件系统 FSFS / BDB，云存储需外部网关与复杂改造
并发写正确性 单写者强一致：repo 级串行 + CommitTxn 原子合并。同路径并发提交被明确拒绝（E160024）、零丢失更新；不同路径并发提交原子合并 乐观锁（wc 基线与 HEAD 冲突）→ 高并发同路径触发 E160024，需客户端 merge / resolve 重试
修订完整性 并发提交下修订号严格连续、无空洞、无错乱；已通过 10 / 20 / 32 并发提交实测 依赖客户端冲突重试，冲突多时修订出现时序波动
故障恢复 混合主备镜像：主本地盘 + 备 S3，停主后备自动接管读；主恢复后自动补齐落后修订 无内置镜像 / 故障切换，容灾依赖外部存储方案
认证与授权 OpenLDAP + 本地密码表认证链，路径级 authz 文件，多库各自独立认证与授权 htpasswd / 外部 LDAP，配置分散、粒度有限
完整性自检 内置 svnadmin verify：遍历 HEAD 树、node-rev CRC 校验 + delta 链回放，自动检测损坏 svnadmin verify 依赖 FSFS 文件完整性，无镜像级自愈

核心优势

原子性 / 并发 / 运维

原子写安全，杜绝丢失

CommitTxn 采用路径级乐观并发控制：目标路径在基线后被其他提交修改即拒绝，不静默覆盖。配合内容哈希 ETag 的 CAS，同一文件并发提交只有一个胜者、其余明确拒绝（E160024）。

同路径并发：0 丢失更新

强一致并发，修订连续

单写者串行模型天然规避乐观锁冲突：多客户端并发提交时修订号严格递增、无空洞、无错乱，写入结果读回一致。

10 / 20 / 32 并发提交全通过

云原生存储与容灾

直接以 S3 / RustFS 对象存储为后端，支持本地盘 + S3 混合主备镜像：故障时备自动接管读，主恢复后自动补齐落后修订，读写下探性自动恢复。

主备镜像故障切换闭环

极简运维，单二进制

一个可执行文件完成启动、多库托管、镜像、验证；--config 声明式配置，无 Apache 依赖，跨环境一致部署。

零外部运行时依赖

完整认证与授权链

OpenLDAP direct-bind + 本地密码表组成的认证链，配合路径级 authz 文件，多仓库各自独立认证与授权，已用真实 OpenLDAP 端到端验证。

LDAP + 本地表 + authz

千万修订级线性扩展

自动分片打包 + 增量 delta 链设计，1000 万修订压测性能线性扩展；大目录列举经 O(n²) 消除后提速约 4.3×。
